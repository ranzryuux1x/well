PROJECT 1: CHIKALOCK TELEGRAM OWNER BOT

==================================================

DIRECTORY:

/workspace/abc/ChikaMD/ProjectBaru/ChikaLock-Bot/

PLATFORM:

- Node.js 20+
- CommonJS
- Telegram Bot API
- Long Polling
- GitHub Contents API

FUNGSI UTAMA:

Telegram Bot berfungsi sebagai panel administrasi untuk mengelola pengguna ChikaLock.

COMMAND:

/start
/daftar USER, PASS, NOMOR
/block NOMOR
/unblock NOMOR
/hapus NOMOR
/list
/blocked
/cek NOMOR

DETAIL FITUR:

1. OWNER AUTHENTICATION

- Hanya OWNER_ID yang boleh menggunakan command administratif.
- Validasi Telegram numeric ID.
- Pengguna lain tidak boleh mengakses database.
- Tolak semua command administratif dari non-owner.

2. REGISTRATION

Format:

/daftar Ranz, RanzRyuu, 628123456789

Data:

- USER
- PASS
- NOMOR

Proses:

- Validasi seluruh input.
- Periksa duplikasi USER.
- Periksa duplikasi NOMOR.
- Hash password menggunakan Argon2id.
- Generate ID_NUM secara random dan unik.
- Simpan data ke REGISTERED.
- Perbarui database GitHub.
- Berikan hasil registrasi kepada owner.

Password plaintext tidak boleh disimpan.

3. BLOCK SYSTEM

Format:

/block 628123456789

Proses:

- Cari akun berdasarkan NOMOR.
- Tambahkan nomor ke BLOCK.
- Simpan alasan block jika diberikan.
- Perbarui GitHub.
- Kirim notifikasi kepada owner.

4. UNBLOCK SYSTEM

Format:

/unblock 628123456789

Proses:

- Hapus nomor dari BLOCK.
- Jangan menghapus data REGISTERED.
- Perbarui GitHub.

5. DELETE SYSTEM

Format:

/hapus 628123456789

Proses:

- Tampilkan konfirmasi sebelum menghapus.
- Hapus akun dari REGISTERED.
- Tangani BLOCK sesuai kebijakan penghapusan yang konsisten.
- Perbarui GitHub.

6. LIST SYSTEM

/list:

- Tampilkan akun terdaftar.
- USER.
- NOMOR.
- ID_NUM.
- Status akun.

Jangan tampilkan PASS_HASH.

7. BLOCKED LIST

/blocked:

- Tampilkan seluruh nomor yang diblokir.
- Tampilkan alasan block jika tersedia.

8. CHECK ACCOUNT

/cek NOMOR:

- Periksa status akun.
- Tampilkan REGISTERED, BLOCKED, atau NOT_REGISTERED.

9. GITHUB INTEGRATION

Gunakan GitHub Contents API untuk:

- Membaca database.
- Memperbarui database.
- Mengambil SHA terbaru.
- Mengatasi HTTP 409 conflict.
- Melakukan retry dengan membaca ulang database terbaru.
- Menghindari overwrite perubahan terbaru.

Jangan menggunakan GitHub Raw URL untuk menulis database.

10. ENVIRONMENT

Buat .env.example:

BOT_TOKEN=
OWNER_ID=
GITHUB_TOKEN=
GITHUB_OWNER=
GITHUB_REPO=
GITHUB_BRANCH=main
GITHUB_DATABASE_PATH=database.json

GITHUB_TOKEN hanya berada di Telegram Bot.

Jangan pernah menampilkan token melalui log atau Telegram.

PROJECT 2: CHIKALOCK GITHUB DATABASE

==================================================

DIRECTORY:

/workspace/abc/ChikaMD/ProjectBaru/ChikaLock-Database/

FILE UTAMA:

database.json

FORMAT:

{
"REGISTERED": [],
"BLOCK": []
}

REGISTERED STRUCTURE:

{
"USER": "Ranz",
"PASS_HASH": "$argon2id$...",
"NOMOR": "628123456789",
"ID_NUM": "839201746"
}

BLOCK STRUCTURE:

{
"NOMOR": "628999999999",
"REASON": "Owner Blocked"
}

DATABASE RULES:

1. REGISTERED menyimpan pengguna yang terdaftar.
2. BLOCK menyimpan nomor yang diblokir.
3. NOMOR menjadi identitas utama pencarian.
4. ID_NUM harus unik.
5. PASS_HASH harus menggunakan Argon2id.
6. Jangan menyimpan password plaintext.
7. BLOCK memiliki prioritas tertinggi.
8. Nomor yang tidak ditemukan dalam REGISTERED dianggap NOT_REGISTERED.
9. Unblock tidak otomatis menghapus akun dari REGISTERED.
10. Penghapusan akun harus menjaga konsistensi REGISTERED dan BLOCK.

GITHUB HOSTING:

Database akan dihosting melalui GitHub Repository.

Contoh Raw URL:

https://raw.githubusercontent.com/OWNER/REPOSITORY/BRANCH/database.json

KETENTUAN:

- Repository sebaiknya private.
- Jika private, gunakan GitHub API dengan read-only credential untuk Vercel.
- Telegram Bot menggunakan GitHub Contents API dengan izin tulis.
- Vercel hanya memiliki izin baca.
- Jangan menyimpan token GitHub di database.json.
- Buat dokumentasi format database.

Tidak perlu membuat aplikasi Node.js tersendiri untuk database.

PROJECT 3: CHIKALOCK VERCEL LICENSE API

==================================================

DIRECTORY:

/workspace/abc/ChikaMD/ProjectBaru/ChikaLock-API/

PLATFORM:

- Vercel Serverless Functions.
- Node.js.
- CommonJS.
- JavaScript.

ENDPOINT:

GET /api/scriptlock/[nomor]

CONTOH:

https://DOMAIN.vercel.app/api/scriptlock/628123456789

TUGAS:

1. Menerima NOMOR dari URL.
2. Mengambil database.json dari GitHub.
3. Memeriksa BLOCK terlebih dahulu.
4. Memeriksa REGISTERED.
5. Mengembalikan status lisensi.
6. Tidak mengubah database.
7. Tidak membocorkan PASS_HASH.

LOGIC:

IF NOMOR EXISTS IN BLOCK:
STATUS = BLOCKED

ELSE IF NOMOR NOT EXISTS IN REGISTERED:
STATUS = NOT_REGISTERED

ELSE:
STATUS = AUTHORIZED

Jika database gagal diakses:
STATUS = ERROR

RESPONSE AUTHORIZED:

{
"status": "AUTHORIZED",
"message": "Access Granted"
}

RESPONSE BLOCKED:

{
"status": "BLOCKED",
"message": "YOUR HAS BLOCK"
}

RESPONSE NOT_REGISTERED:

{
"status": "NOT_REGISTERED",
"message": "YOU ARE NOT REGISTERED"
}

RESPONSE ERROR:

{
"status": "ERROR",
"message": "LICENSE SERVER ERROR"
}

SECURITY:

1. Implementasikan Ed25519 signed response.
2. Private signing key hanya berada di environment Vercel.
3. Public key disediakan untuk NPM Package.
4. GitHub credential hanya memiliki izin baca.
5. Tambahkan timeout request.
6. Validasi format NOMOR.
7. Jangan membocorkan PASS_HASH.
8. Fail closed jika database tidak tersedia.
9. Fail closed jika signature tidak valid.
10. Tambahkan timestamp dan expiry pada signed response.
11. Gunakan nonce atau request identifier untuk mengurangi risiko replay.
12. Jangan menggunakan in-memory rate limiting sebagai proteksi global.
13. Jangan memberikan respons AUTHORIZED jika proses validasi gagal.

ENVIRONMENT:

GITHUB_READ_TOKEN=
GITHUB_OWNER=
GITHUB_REPO=
GITHUB_BRANCH=main
GITHUB_DATABASE_PATH=database.json
ED25519_PRIVATE_KEY=

PUBLIC KEY harus dibuat menggunakan mekanisme key generation yang sesuai dan diberikan kepada pemilik package untuk konfigurasi.

PROJECT STRUCTURE:

ChikaLock-API/
│
├── api/
│   └── scriptlock/
│       └── [nomor].js
├── src/
│   ├── github.js
│   ├── license.js
│   └── signature.js
├── package.json
├── vercel.json
└── README.md
